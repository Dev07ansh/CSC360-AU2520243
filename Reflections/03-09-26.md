# Class Reflection
- Text-based interfaces are essential for robust remote interaction with headless computing environments like HPC nodes
- User Experience (UX) design, including visual feedback like progress bars and splash screens, is crucial for preventing user confusion
- Software development best practices include Test-Driven Development (TDD) and the use of unit tests to ensure system reliability
- Advanced application features like tree-based object editing and composite progress tracking require careful management of state, serialization, and thread lifecycle

## Keywords
Headless computing, SSH, UX design, Test-Driven Development (TDD), Unit testing, Thread cancellation, Serialization, JavaFX


## List of topics discussed:
- **Text vs. Graphical Interfaces** – robustness of terminal-based interaction for headless environments
- **Software Engineering Principles** – TDD, unit vs. acceptance tests, CI/CD
- **UX and Application Design** – splash screens, information density, graceful cancellation


## Notes

### Topic 1 - Text vs. Graphical Interfaces
- Text is more robust for remote, headless environments where monitors are absent
- Terminal-based interaction is the standard for connecting to servers via SSH
- Drawing structures like trees in a console requires careful handling of terminal width and character-based formatting

### Topic 2 - Software Engineering Principles
- **Test-Driven Development (TDD):** write tests before implementation to ensure code quality
- **Unit Tests vs. Acceptance Tests:** unit tests verify specific logic; acceptance tests verify overall system functionality
- **CI/CD:** continuous integration ensures automated tests run on every code change to keep the system stable

### Topic 3 - UX and Application Design
- **Splash screens:** provide visual feedback during startup to prevent users from repeatedly launching the application
- **Information density:** avoid overwhelming users with excessive data; use techniques like compression or selective display for large datasets
- **Graceful Cancellation:** threads should be signaled to stop rather than killed abruptly, allowing for resource cleanup (e.g., closing files)
